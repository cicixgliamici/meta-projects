# Docker Fundamentals

This document provides the theoretical foundation for containerization, which powers modern software delivery and DevOps practices.

## Containerization vs. Virtualization

Traditionally, to run isolated applications, we used **Virtual Machines (VMs)**. A VM includes the application, the necessary binaries/libraries, and an entire Guest Operating System (Guest OS), which sits on top of a Hypervisor. VMs are heavy and slow to start.

**Containers**, on the other hand, sit on top of a Container Engine (like Docker). They package the application and its dependencies but **share the Host Operating System's kernel**. This makes them:
- Extremely lightweight (often megabytes instead of gigabytes).
- Fast to start (seconds or milliseconds).
- Highly portable ("it works on my machine, and it will work in production").

## Core Concepts

### 1. Image
A Docker image is a read-only, immutable template with instructions for creating a Docker container. It contains the application code, libraries, tools, dependencies, and other files needed to make an application run. Images are built using a `Dockerfile`.

### 2. Container
A container is a runnable instance of an image. If an image is a "class" in object-oriented programming, the container is the "object" (instance). Containers are ephemeral; if you delete a container, any data written inside it is lost unless persisted explicitly.

### 3. Layers
Docker images are built in layers. Every instruction in a `Dockerfile` (like `RUN`, `COPY`, `ADD`) creates a new layer. Docker caches these layers. If you change a line of code, Docker only rebuilds the layer containing your code and the layers below it, reusing the cached OS and dependency layers, making builds extremely fast.

### 4. Volumes
Because containers are ephemeral, we need a way to persist data (e.g., database files). **Volumes** are the preferred mechanism for persisting data generated by and used by Docker containers. A volume is essentially a directory on the host machine that is mounted directly into the container.

### 5. Networks
Docker networks allow containers to communicate with each other in complete isolation from the outside world. When you use `docker-compose`, Docker automatically creates a custom network for your application stack, allowing the API container to talk to the Database container simply using the database's service name as the hostname.
